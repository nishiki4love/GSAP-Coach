# GSAP Coach 教学流程产品体验评估

评估日期：2026-05-31  
评估视角：产品经理 + 初次访问用户 + 有一定前端基础但不熟悉 GSAP 的学习者  
评估范围：演示工作台、教程、覆盖矩阵、滚动实验、插件实验室、性能指南

## 一句话结论

当前网站的资料覆盖面和演示能力已经比较扎实，但教学流程还更像“API 演示与资料库”，不像一条清晰的课程路径。用户能看到很多有价值内容，却不够明确知道“先学什么、学到哪一步、下一步做什么、怎样算学会”。

综合判断：

- 教学内容完整度：高。覆盖 Core、Timeline、ScrollTrigger、插件、Utils、框架集成和性能。
- 教学流程清晰度：中。页面拆分合理，但缺少主线、进度、任务和章节内闭环。
- 上手易用性：中。工作台有可互动舞台，但新用户不容易理解控件和教程之间的关系。
- 查阅效率：中高。覆盖矩阵适合查 API，但缺少搜索、筛选和明确跳转反馈。
- 移动端体验：中低。窄屏下核心导航和 API 详情容易被埋到页面下方，学习连续性变弱。

## 当前教学流程梳理

用户进入网站后，默认落在“GSAP 功能演示工作台”。首页结构大致是：

1. 选择演示类型：Tween、Timeline、ScrollTrigger、插件、Utils。
2. 在舞台观察动画效果。
3. 在控制面板选择 API。
4. 在详情卡片阅读 API 说明、代码片段和所属章节步骤。
5. 通过顶部或侧边导航进入教程、覆盖矩阵、滚动实验、插件实验室、性能指南。

其他页面的作用：

- 教程页：按 7 个主题给出学习步骤和 API 快捷入口。
- 覆盖矩阵：按 skill 分组列出 84 个 API、说明和覆盖状态。
- 滚动实验：单独展示 ScrollTrigger 的 pin、scrub、containerAnimation 和清理刷新。
- 插件实验室：集中展示插件类 API，并提供 Flip 布局切换演示。
- 性能指南：整理动画性能原则和代码片段。

这个信息架构本身是合理的：工作台负责“看见动画”，教程负责“建立知识框架”，覆盖矩阵负责“查全量 API”，专题页负责“深入练习”。问题在于这些页面之间还没有形成一个足够明确的学习闭环。

## 主要问题

### 1. 首屏目标不够像“开始学习”

首页首屏强调“演示工作台”，但对初学者来说，最先需要的是一个明确入口：从哪里开始、预计学多久、第一节课完成什么。当前首屏能看到很多控件和概念，但缺少类似“从第 1 课开始”“继续学习”“先看 5 分钟入门”的产品引导。

用户感受：

- 我知道这是 GSAP 相关工具，但不确定它是课程、文档、实验室还是 API 查询器。
- 我能点动画 tab，但不知道这些 tab 和完整课程顺序是什么关系。

建议：

- 首页增加一个主学习 CTA：`开始第 1 课：Tween 基础`。
- 增加“推荐学习路径”模块：`新手入门 -> Timeline 编排 -> ScrollTrigger -> 插件 -> 性能优化`。
- 给每个阶段标注学习目标和预估时长，例如“10 分钟，掌握 targets + vars + tween 控制”。

### 2. 教程页是章节清单，不是完整课程页

教程页按主题列出步骤，这是好的，但每个章节目前只有简短检查点和 API 按钮。它缺少教学型页面常见的“概念解释 -> 观察演示 -> 动手练习 -> 检查结果 -> 下一节”的结构。

用户感受：

- 我读完步骤后，仍然不知道应该在哪里动手。
- API 按钮会跳回工作台，但没有明确告诉我“接下来应该观察哪个舞台变化”。

建议：

- 将每个章节升级为独立详情页，例如 `/tutorials/core`、`/tutorials/timeline`。
- 每节课采用固定模板：
  1. 学习目标
  2. 核心概念
  3. 观察演示
  4. 修改参数练习
  5. 常见错误
  6. 完成检查
  7. 下一节
- 保留当前教程页作为课程目录，而不是承载全部教学内容。

### 3. API 跳转反馈不够明显

从教程页、覆盖矩阵、插件实验室点击 API 后，会跳回工作台并更新右侧详情。但在移动视口下，用户首先看到的是工作台顶部和舞台，不一定能立刻看到刚才点击的 API 详情。这个跳转容易造成“点击好像没反应”或“我被带回首页了”的错觉。

用户感受：

- 我点了 `gsap.registerPlugin()` 的“查看教程”，结果回到工作台顶部，需要自己找变化。
- 覆盖矩阵行可点击，但没有明显提示点击后会发生什么。

建议：

- API 跳转后自动滚动并聚焦到 API 详情卡片。
- 在工作台顶部显示短暂提示：`已打开 gsap.to() 详情`。
- URL 带上选中 API，例如 `/?api=gsap-to`，支持刷新和分享。
- 覆盖矩阵行增加显式操作按钮，例如 `查看详情`，降低隐性点击成本。

### 4. 练习和完成标准缺失

网站已经有代码片段和动画舞台，但缺少“让用户做一件事”的任务。教学产品不能只告诉用户知识点，还需要让用户完成动作并获得反馈。

用户感受：

- 我看到了示例代码，但没有被要求改 duration、ease、x 或 timeline position。
- 我无法判断自己是不是已经掌握当前章节。

建议：

- 每个章节增加 2 到 3 个小练习，例如：
  - 修改 `duration` 和 `ease`，观察运动差异。
  - 把一个 `delay` 写法改成 timeline position parameter。
  - 给 ScrollTrigger 示例增加 `scrub: true` 并比较效果。
- 增加完成检查清单，例如：
  - 能解释 targets 和 vars 的区别。
  - 能用 `gsap.to()` 做一次位移动画。
  - 能保存 tween 并调用 `pause()` / `reverse()`。
- 对练习给出即时反馈或参考答案。

### 5. 页面之间的学习关系不够显性

现在的页面分工清楚，但用户需要自己推断关系：教程讲 ScrollTrigger，滚动实验也讲 ScrollTrigger；教程讲插件，插件实验室又是另一个页面；性能指南与性能章节也有关联。缺少跨页面的上下文串联。

建议：

- 每个专题页顶部增加“你在学习路径中的位置”，例如：
  - `第 3 章 ScrollTrigger -> 滚动实验 -> 性能注意事项`
- 滚动实验页增加返回教程章节的入口：`回到 ScrollTrigger 课程`。
- 插件实验室按教程章节排序，并在每张卡片中显示“推荐先学 / 进阶 / 开发专用”。
- 性能指南增加“适合在完成 Core 和 ScrollTrigger 后阅读”的提示。

### 6. 移动端导航优先级需要重排

移动视口下，顶部只露出侧边栏按钮、覆盖矩阵、主题和语言。对学习网站来说，“教程”比“覆盖矩阵”更像主入口。当前移动端容易让新用户优先进入 API 表格，而不是学习路径。

建议：

- 移动端顶部主按钮改为 `教程` 或 `继续学习`。
- 保留覆盖矩阵入口，但放到二级菜单或页面底部。
- API 详情卡片在移动端可以前置到舞台后方，并在跳转后直接滚动到详情。

### 7. 覆盖矩阵更适合查阅，但还缺少查阅工具

覆盖矩阵价值很高，尤其适合验证 API 覆盖状态。但列表很长，当前没有搜索、筛选、状态过滤或按关键词定位。

建议：

- 增加搜索框：支持 API 名称、signature、summary。
- 增加状态筛选：`互动演示`、`教程覆盖`、`开发专用`。
- 增加分组筛选：Core、Timeline、ScrollTrigger、Plugins、Utils、React、Performance。
- 点击 API 后保留来源上下文，例如详情页提供“返回覆盖矩阵当前位置”。

## 建议的新教学流程

推荐将网站体验改成“三层结构”：

### 第一层：学习路径

面向初学者，目标是降低开始成本。

首页优先展示：

- 当前推荐课程：`GSAP 入门路径`
- 下一步按钮：`开始学习` / `继续学习`
- 进度：`0/7 章节`
- 预计时间：`约 60 分钟完成基础路径`

### 第二层：章节课堂

面向系统学习，目标是形成闭环。

每章固定结构：

- 目标：本章学会什么。
- 概念：用短文解释核心心智模型。
- 演示：嵌入当前工作台舞台或跳转到对应 demo。
- 练习：让用户修改参数或完成一个小任务。
- 检查：用 3 个问题确认理解。
- 下一步：跳到下一章或专题实验。

### 第三层：资料与实验室

面向查阅和进阶，目标是提高深度。

- 覆盖矩阵：API 索引、状态、搜索、筛选。
- 滚动实验：ScrollTrigger 专题练习。
- 插件实验室：插件目录和互动示例。
- 性能指南：开发前检查清单。

## 修改建议优先级

### P0：先补教学主线和跳转反馈

这些改动投入不大，但能明显改善用户是否“知道下一步做什么”。

- 首页增加 `开始学习` / `继续学习` 主 CTA。
- 教程页增加章节顺序、预估时间和完成目标。
- API 点击跳转后自动滚动到详情卡片，并显示选中 API 提示。
- URL 增加 `api` 参数，支持分享和刷新保持选中状态。
- 移动端顶部主入口从 `覆盖矩阵` 调整为 `教程` 或 `继续学习`。

### P1：把教程升级成可完成的课程

这些改动会把网站从资料型工具提升为教学产品。

- 为每个章节建立独立课程页。
- 增加章节练习、检查清单和参考答案。
- 建立课程进度状态，可先用 localStorage 实现。
- 将滚动实验、插件实验室和性能指南串回对应章节。
- 覆盖矩阵增加搜索和筛选。

### P2：增强学习反馈和留存

这些改动适合基础流程稳定后再做。

- 章节完成徽章和学习记录。
- 收藏 API / 收藏代码片段。
- 小测验或选择题。
- “常见错误”案例库。
- 根据用户已完成章节推荐下一步实验。

## 页面级修改建议

| 页面 | 当前定位 | 主要问题 | 建议 |
| --- | --- | --- | --- |
| 演示工作台 | 动画观察与 API 详情 | 初学者不知道如何开始；API 详情在移动端容易被埋 | 增加学习 CTA、选中 API 提示、跳转后聚焦详情 |
| 教程 | 学习路径目录 | 只有步骤摘要，没有章节闭环 | 拆为课程目录 + 章节详情页 |
| 覆盖矩阵 | API 全量索引 | 列表长，缺搜索筛选；行点击反馈弱 | 增加搜索、筛选、显式查看详情按钮 |
| 滚动实验 | ScrollTrigger 专题演示 | 与教程章节关系不明显 | 增加“来自第 3 章”的上下文和返回入口 |
| 插件实验室 | 插件 API 展示 | “查看教程”实际跳到工作台，语义不准 | 改成“查看详情”或真的进入插件课程 |
| 性能指南 | 性能实践清单 | 内容有价值，但像孤立资料页 | 增加适用阶段、前置知识和动手检查项 |

## 可执行改版路线

### 第 1 步：不改数据结构，先增强导航和反馈

验证方式：

- 从教程页点击任意 API 后，页面自动到达详情卡片。
- 移动端用户能在首屏看到 `开始学习` 或 `教程` 主入口。
- 刷新 `/?api=gsap-to` 后仍打开 `gsap.to()` 详情。

### 第 2 步：增加课程目录信息

验证方式：

- 教程页每章都有目标、预估时间、难度和下一步入口。
- 用户能清楚知道 7 个章节的推荐学习顺序。

### 第 3 步：建立第一版章节详情页

验证方式：

- 至少完成 Core Tween 章节详情页。
- 页面包含目标、概念、演示、练习、检查、下一节。
- 用户不需要离开章节页也能完成一次基础学习闭环。

### 第 4 步：补齐查阅效率

验证方式：

- 覆盖矩阵可以搜索 `ScrollTrigger`、`quickTo`、`SplitText`。
- 可以只查看 `互动演示` 或 `教程覆盖`。
- 从 API 详情返回覆盖矩阵时保留筛选条件。

## 成功指标建议

可以用以下指标衡量改版是否有效：

- 新用户从首页点击 `开始学习` 的比例。
- 第 1 章完成率。
- 从教程页点击 API 后，用户是否继续停留在工作台超过 20 秒。
- 覆盖矩阵搜索使用率。
- 移动端跳出率是否下降。
- 用户完成 ScrollTrigger 章节后进入滚动实验的比例。

## 总结

GSAP Coach 的基础资产已经很好：内容覆盖广、演示真实、代码片段充足，也有中英文和主题切换等成熟产品细节。下一阶段最重要的不是继续堆 API，而是把现有内容组织成“能被完成”的教学路径。

优先建议是：先让首页更像课程入口，让 API 跳转有明确反馈，让教程页从“章节摘要”升级为“可继续学习的路径”。做到这三点后，用户会更容易从“我看到了很多内容”转变为“我知道现在该学什么，而且能一步一步学完”。
